# Device tests

Devices behave differently (MTP especially varies by manufacturer), so the same tests are run on every phone we want to support.
When a test fails, fix the implementation, not the test: work around the behavior, or block what can't work with a clear error.
New device behavior goes into `QUIRKS.md`.

## Safety: running on your own phone

The tests are safe to run on a phone you use every day.

- On the phone, tests only write inside a folder they create themselves under `/sdcard/Download/xfer-*` (`xfer-devtest-<time>`, `xfer-devtest-pair-<time>` for two devices, `xfer-queuetest-<time>` for the queue test), and delete it when done. They never read or change any other file.
- All files are random data generated by the test. Temporary folders on the Mac are deleted when done too.
- If a run stops midway and leaves its folder behind, delete the path it printed at startup from the phone.
- During an MTP test, make sure no other app (Photos, this app, etc.) is using the phone. Only one program can use MTP at a time.

## Automated tests (`sferry devtest`)

```sh
make cli                                      # or: cd Packages/SolidFerryKit && swift build --product sferry
sferry -s SERIAL devtest adb [quick]          # phone with USB debugging on
sferry -s SERIAL devtest mtp [quick]          # phone in File transfer (MTP) mode
sferry devtest-pair A:adb B:mtp [quick]       # two phones (each connection is adb|mtp)
```

- The tests run against the same `DeviceFileSystem` interface as the app, so ADB and MTP share the same tests.
- `quick` shrinks the tests with many files (300 → 60 files).
- At the end it prints ✔/✘ per test with the failure reason, and exits with code 1 if anything failed.
- To run a single test: `XFER_DEVTEST_ONLY="part of the name"`. To keep the test folder on the phone after a failure: `XFER_DEVTEST_KEEP=1` (delete it yourself afterwards).

**Two devices (`devtest-pair`)**: uses the same code as the app (`DeviceToDevice` to copy, `ExistingItem` and `FileDecision` to decide what to skip):
- Copy files made on A (10 and 100 small files, 5 MB, subfolders, 2024 dates) to B → same bytes, sizes, and folder structure
- Dates are kept (if B is a phone that doesn't keep dates, this is detected)
- Copying again skips everything as "same"; a single file changed on B is the only one copied again, and it is restored to the original
- Receive from A and send to B at the same time
- Copy B → A
- Pause a 32 MB copy at the 4 MB mark → B has either one complete file or nothing (an MTP target receives it to the end), and the next copy works
- No temporary files left on either phone or the Mac

The combinations (ADB→ADB, ADB→MTP, MTP→ADB, MTP→MTP) are covered by changing only the connection types. The same phone twice (A=B) is rejected.

**Transfer queue, end to end through the app (`scripts/queue-test.sh`)**: runs a development build of the app once per step with launch arguments (`-dev.download`, `-dev.upload`, `-dev.deviceCopy`, `-dev.quitWhenDone result.json`), then checks the job results (copied, skipped, failed counts) and the files on the Mac and the phone (md5).

```sh
make build && scripts/queue-test.sh A[:adb|mtp] B[:adb|mtp]   # connection the app uses (default adb). Setup and checks use adb, so both phones need USB debugging
```

- A → Mac download (dates kept); downloading again to the same place skips everything; downloading again with the content-compare (hash) policy also skips everything (when A is ADB)
- Mac → B upload, A → B device-to-device copy
- Copying again copies only the one file changed on B and skips the rest; no temporary files left
- Run it after changing queue processing, conflict policies, or the device-to-device copy path. Quit the app first if it is running.
- Pass different settings with `APP_ARGS`. For example, direct writes: `APP_ARGS="-writeNewFilesDirectly YES -writeReplacedFilesDirectly YES"`.
- If a step doesn't finish within 120 seconds, the app window just before it is saved to `$TMPDIR/xfer-queuetest-stuck-<time>`. The window shows the device's real folders, so turn this off with `SNAPSHOTS=0` on devices whose contents must not be captured.
- Direct-write speed comparison: `sferry -s SERIAL upload-bench adb|mtp [count] [KB]` (uses its own folder, deleted when done).
- Device-to-device copy speed comparison: `sferry copy-bench A:adb|mtp B:adb|mtp MB` — uploads a generated file to its own folder on A, then copies it to B directly, through a temporary file on the Mac, and directly again; each copy is downloaded back from B and compared byte for byte (that copy is deleted right away). Both folders are deleted when done. A and B may be two connections to the same device (`X:adb X:mtp`).

**Two jobs at once, two phones (`scripts/two-jobs-test.sh`)**: same approach, with two jobs queued together (`;`-separated entries in `-dev.deviceCopy` and `-dev.download`).

```sh
make build && scripts/two-jobs-test.sh A[:adb|mtp] B[:adb|mtp]
```

- Device-to-device copies A → B and B → A together (each job uses both phones): 200 files each way, contents match
- A and B download into the same Mac folder together (200 files each, same names, different contents): each file is received exactly once (200 copied in total) and the rest are skipped as "already exists"; every file on the Mac matches one of the phones exactly; no hidden or temporary files
- How much the jobs overlap depends on speed: if one side is much faster (ADB vs. MTP), it finishes first and they don't overlap. To see overlap, also run it with ADB and ADB.
- Run it after changing the download rule "a file planned as new doesn't overwrite a file that appeared in the meantime". No window capture.

**Pause → resume, one phone (`scripts/pause-test.sh`)**: same approach. Two jobs that overwrite existing files (copy within the phone, and upload from the Mac: one 300 MB file plus 20 small files) are paused 0.3, 1, and 2 seconds after starting (`-dev.pauseAfter seconds`), then resumed. At the end every file must match the original, with no temporary or moved-aside files left.

```sh
make build && scripts/pause-test.sh SERIAL[:adb|mtp] [seconds…]
```

- If the pause lands after the job has finished, it reports "(finished before the pause)" (e.g. 2 seconds on a fast phone). `paused` in the result JSON indicates this.
- Run it after changing pause/resume, overwriting (moving the original aside), or transfer progress. No window capture.

**Many files, one phone (`scripts/bigtest.sh`)**: same approach, with 10,000 files (1.1 GB). Covers batched listing of a large folder (8,000 files), the queue lining up two MTP files, content comparison (hashing alongside), whole-folder copy and move within the same phone, and merging. The test files are created once (about 8 minutes) and reused:

```sh
D=/sdcard/Download/xfer-bigtest-$(date +%s)
adb -s S shell "mkdir -p $D/src/Camera && cd $D/src/Camera && i=1; while [ \$i -le 7998 ]; do n=\$(printf %05d \$i); head -c \$(( (RANDOM % 180 + 20) * 1024 )) /dev/urandom > IMG_\$n.jpg; i=\$((i+1)); done; head -c 100000000 /dev/urandom > VID_00001.mp4; head -c 100000000 /dev/urandom > VID_00002.mp4; for s in \$(seq -w 1 20); do mkdir -p $D/src/Docs/sub\$s; j=1; while [ \$j -le 100 ]; do head -c \$(( (RANDOM % 20 + 1) * 1024 )) /dev/urandom > $D/src/Docs/sub\$s/doc\$j.txt; j=\$((j+1)); done; done; touch -d '2023-05-06 07:08:09' $D/src/Docs/sub01/*"
make build && scripts/bigtest.sh S adb|mtp $D   # MTP: File transfer mode with the screen kept on (svc power stayon usb; set back to false when done)
```

- Download → download again (skipping by size and date; over ADB, only the 5 files changed on the Mac to the same size are downloaded again via content comparison) → upload → upload again (over MTP, size only on phones that don't keep dates) → whole-folder copy within the phone → merge into a folder with the same name → whole-folder move; no temporary files left
- Results of earlier runs (`up-`, `copy-`, `moved-<connection>`) are deleted at the start; `src` is kept.

**Test list**

| Test | What it checks | Related |
|---|---|---|
| Create folder, list empty folder | A new folder shows up as a folder | |
| Upload: size and date kept | Modification time within ±2 s, or, on phones that can't keep dates, the connection info says so | Galaxy MTP |
| Folder dates | Where the connection can set them (ADB), a folder with a file in it takes the date it's given, within ±2 s | QUIRKS A21 |
| Boundary-size transfers | Upload and download at 0, 1, 511, 512, 513, 1023, 1024 B, around 1 MB, and around 8 MB return exactly the same bytes | USB packets (512/1024), 1 MB upload chunks, 8 MB download chunks, Samsung last-packet issue |
| Read into memory | Parts of the files above read into memory (as the preview window does) match byte for byte; with a 1 MB limit, the 8 MB file stops partway and the connection keeps responding | Preview window (`RemoteContents`), reads stopped partway |
| Range reads | On an 8 MB file: the first byte, ranges spanning packet and 1 MB boundaries, to the end, and the whole file are exact. After stopping a full read partway, another range is still exact | Reading while playing (MTP GetPartialObject64, ADB `dd`), reads discarded when seeking |
| Names: names Android rejects | Names containing `" : * ? < > \| \` are rejected up front with a clear error | QUIRKS: shared storage naming rules |
| Names: special characters | Spaces, `'`, `$`, backtick, Korean, emoji, 200 characters, hidden files. Shell quoting and encoding | |

| Failed overwrite | Overwriting with an unreadable local file fails → original unchanged | Protecting the original |

| Copy within device: folder | The whole folder is copied | MTP copies item by item |

| Move within device: folder, with a new name | | |
| List: 300 files | Count and sizes | |
| Batch download: one file fails | One unwritable local location → only that file fails, the rest are downloaded | |
| Delete | A file and a non-empty folder | |
| Hash on the phone (ADB) | md5 matches the Mac's | |
| Copy and move within device as planned | Passing what was seen at planning time (`replacing`): copy onto an existing file, copy to an empty name, and move to a different name (keeping both) all work without reading the folder again | QUIRKS G5, M15 |

## Manual tests

Things that are hard to automate (they need a cable, the phone's screen, or the app's UI).

| Test | How | Expected |
|---|---|---|
| Unplug the cable during a transfer | Unplug and replug during a large upload/download in the app | Original kept; the job waits for the device and continues |
| Unplug the cable → Wi-Fi | Unplug while browsing in the app with wireless debugging on | Continues over Wi-Fi within 2 seconds; back to USB when replugged |
| [Connect over Wi-Fi] button | Press the button with wireless debugging off | Phone shows an allow prompt → connects. On a different router: "not reachable" |
| MTP phone already claimed by the Photos service | Plug in an MTP phone with Photos open | Takes over and connects; while waiting, shows the reason and a Settings button |
| Charging only → File transfer | Plug in in charging mode, then choose File transfer on the phone | Connects automatically |
| USB keeps dropping | A cable with a bad connection | The device entry shows "USB connection keeps dropping" |
| Drag, ⌘C/⌘V, batch rename, text size | The app's UI | Each window appears and the results are correct |
| Copy between two devices (app) | Check in the app UI after `devtest-pair` passes. `-dev.deviceCopy "A>B\|/source\|/targetFolder\|copy"` | Progress and results (copied, skipped counts) are correct. Two phones of the same model are told apart by the last digits of the serial number after the name |

| Galaxy S10 5G | 12 | All pass | All pass | MTP doesn't keep upload dates (detected by the test). Taken over from the Photos service when it had claimed the device |

Devices worth adding: Pixel (stock Android), Android 8 or earlier (no `ls_v2` → handling 4 GB sizes), below Android 9 (no tar), MTP from other manufacturers such as Xiaomi and OnePlus.
